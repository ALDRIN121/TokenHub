# TokenHub 0.1.8

TokenHub now estimates what the usage it already tracks costs, and the analytics
endpoints answer several times faster on a large history.

## Cost estimates

- The first start writes editable USD rates per million tokens to
  `~/.tokenhub/pricing.json`, covering input, output, cache read and cache
  write for the bundled models. Edit a rate or add a model and TokenHub reloads
  the file on its next read; `TOKENHUB_PRICING_FILE` points at a different file.
- Each model row reports `estimated_cost_usd`. Uncached input is
  `max(input - cache_read - cache_write, 0)` and each component is priced with
  its own rate; a missing cache rate falls back to the input rate. Reasoning
  tokens are already part of output and are not charged twice.
- Model names resolve from the most specific path to the bare name, so
  `openrouter/anthropic/claude-sonnet-5` and `anthropic/claude-sonnet-5` fall
  back to `claude-sonnet-5`. Dated suffixes, aliases and `:tags` resolve too,
  and a prefixed key reprices only that route.
- Models without a published rate stay visible as **Unpriced model** and are
  excluded from cost totals instead of being guessed. They are counted in
  `unpriced_event_count`, and `/api/v1/pricing` reports the active rates,
  warnings and file name.
- `tokenhub pricing` prints the active file and how many models it prices.

## Faster analytics

Every analytics read used to recompute the canonical set: a `UNION ALL` of the
ordinary delta rows plus a `row_number()` window over cross-file Claude and
Codex history. On a 300,000-event history that window alone cost about 1.4
seconds, and each of eight endpoints paid it independently.

- `usage_events_canonical` now stores the deduplicated set. It is refreshed
  inside the ingest transaction for the `(connector_id, record_identity)`
  groups a scan touched, and backfilled once at startup for existing databases.
- Readers — dashboard totals, explorer, quality and observed events — scan the
  projection directly. The ranking rule stays in one place so the raw and
  canonical tables cannot disagree.
- A partial index covers the delta identities the ranking probes, the engine
  uses WAL with `busy_timeout` applied first, and `PRAGMA optimize` plus a WAL
  checkpoint run after an ingest that changed data.
- Concurrent dashboard polls now share one aggregate build, and API reads carry
  an ETag: an unchanged poll returns `304` with no body to parse.

Median of 3–5 runs at 300,000 synthetic events (`scripts/bench_analytics.py`):

| Endpoint | Before | After | Speed-up |
| --- | ---: | ---: | ---: |
| `/api/v1/dashboard` | 2,738 ms | 140 ms | 19.6× |
| `/api/v1/usage/summary` | 5,966 ms | 1,200 ms | 5.0× |
| `/api/v1/usage` (full) | 10,153 ms | 3,508 ms | 2.9× |
| `/api/v1/usage/models` | 3,880 ms | 972 ms | 4.0× |
| `/api/v1/usage/sessions` | 7,444 ms | 3,105 ms | 2.4× |
| `/api/v1/usage/trends` | 12,600 ms | 4,003 ms | 3.1× |

The projection is not free: the same database grows from 108 MB to 189 MB.
Storing the derived rows once is cheaper than recomputing the window on every
request. A first 20,000-event ingest takes 0.88 s including its projection, and
a routine 1,000-event scan 0.05 s because only those identities are re-ranked.

## Upgrade

```sh
python -m pip install --upgrade tokenhub
tokenhub stop
tokenhub start
```

Existing approved sources and usage data are retained. The canonical
projection is backfilled during startup, so the first dashboard load after an
upgrade may take a few seconds on a large history. Requires Python 3.10 or
later.

## Verification

571 backend tests pass (2 skipped) on Python 3.10 and 3.12, including the
projection parity and performance-budget tests; 109 frontend tests pass. Ruff
and mypy are clean, the production dashboard build is checked in, and the
benchmark above reproduces on a 300,000-event database. Models without a
published rate remain unpriced rather than estimated.
